Self-Balancing Motorcycle

A controls project using the Arduino Engineering Kit Rev2 motorcycle platform. The system used flywheel stabilization, stepper-based steering alignment, and encoder feedback to drive forward and stop near a target distance.

Project focus

  • BalanceImplemented and tuned a PD controller for flywheel-based roll stabilization.
  • DriveUsed encoder counts and duty-cycle ramping to move toward the target distance without destabilizing the bike.
  • SteeringHeld the front wheel at a straight reference position because the required path was linear.

Project snapshot

Balancing first, then driving forward.

The motorcycle was programmed to stabilize in place before beginning forward motion. Once balanced, the drive motor ramped up rather than jumping instantly to full duty, reducing slip and sudden disturbances. The flywheel stayed active through acceleration and braking.

Controls implementation

Three control tasks on one unstable platform.

Balance control

  • Used roll feedback to command the flywheel motor.
  • Started from model-based PD gains, then tuned on hardware.
  • Final gains used: Kp = -6601, Kd = -431.
  • Stable runs lasted roughly 30–60 seconds during testing.

Drive control

  • Delayed forward motion until after initial balancing.
  • Ramped motor duty to reduce slipping and balance disturbances.
  • Used encoder feedback to estimate distance traveled.
  • Ramped down drive duty after reaching the stop trigger.

Steering control

  • Used the steering motor to hold a forward-facing reference.
  • Did not require path-following because the task was a straight-line run.
  • Kept steering simple so tuning effort could focus on balance and drive behavior.

Tuning approach

Modeling gave a starting point; hardware tuning made it work.

Controller tuning

A simplified plant model was used in MATLAB to choose initial PD gains. Those values helped get the controller close, but the final behavior depended on real testing because the motorcycle was sensitive to vibration, friction, and small parameter errors.

Observed issue

The main tuning challenge was sign-change behavior: when the roll angle crossed through zero, the bike sometimes undercompensated and fell the other way. Increasing the derivative term improved the response.

The page avoids re-deriving the full physics model because the portfolio-relevant work was the control implementation: getting sensor feedback, motor commands, gain tuning, and drive logic to work together on physical hardware.

Distance control

Encoder counts set the stopping trigger.

Target conversion

The 2 meter target was converted into an encoder-count threshold using the wheel circumference and the motor encoder resolution. The calculated value was then adjusted experimentally.

targetCounts ≈ 1000 · 2 / (2π · 0.038) ≈ 8670

Motion sequence

  • Balance in place for 5 seconds.
  • Ramp drive duty toward maximum speed.
  • Track encoder counts while moving forward.
  • Ramp down drive duty after the target count.

Takeaways

What this project demonstrated.

Technical achievements

  • Implemented a flywheel-based balancing controller on an unstable physical system.
  • Integrated roll feedback, encoder feedback, steering alignment, and motor duty logic.
  • Tuned controller gains and drive ramp behavior through hardware testing.
  • Balanced stopping accuracy against stability during acceleration and braking.

Engineering lessons

  • Controller gains that look acceptable in simulation still need physical validation.
  • Acceleration profile matters as much as the balance controller on a moving platform.
  • Simple control decisions can be more reliable than overcomplicated ones when the task is constrained.
